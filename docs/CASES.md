# AI 案例库

来源：同一 Base 的 `tbldtSGzcfa6twD0`，指定视图 `vew4BiClvU`。当前视图没有显式 sort，后端不附加 sort/filter，按飞书返回顺序分页拼接；前端不按日期、标题或分类重新排序。首页从可展示集合取前三条，案例库按同一集合筛选并每页展示 6 条。

## 请求及缓存

浏览器仅通过已登录同源请求 `GET /api/v1/cases` 获取案例。接口默认鉴权，并可配置来源租户校验。应用身份查询飞书，不依赖 lark-cli 的用户会话。首页、案例库、详情、SkillHub 共用这一份数据源快照，不按用户生成副本。

Redis 键：`<prefix>:cases:v3:<sha256(app_id|base|table|view)前24位>:<suffix>`。

- `fresh`：1800 秒（30 分钟），普通读取不续期。
- `snapshot`：604800 秒（7 天），每次成功刷新重新计算。
- `lock`：60 秒；刷新总超时 45 秒，并发等待者最多等待 10 秒，有旧快照则返回 `stale=true`。
- `cooldown`：刷新失败后 15 秒内不再回源。
- 刷新完成通过 Redis 事务同时更新快照和新鲜标记，防止半成品发布。
- Redis 不可用返回统一 503，不绕开 Redis 向飞书发请求；无旧数据时失败返回统一错误，不使用演示案例冒充真实结果。

这是请求触发更新，不是后台定时推送。飞书改动通常在新鲜期到期后的下一次访问生效；已经打开的页面需重新加载。重试按钮会重新请求后端，仍遵守后端缓存，不允许客户端强制回源。

## 字段和展示

映射作品名、一句话描述、所属团队、第一作者、作品tag、产物类型、案例来源、案例编号、敏感风控、文档 / 链接、封面附件。排除作者邮箱等不需要的字段。

用户确认的展示策略：只排除 `暂不公开`；其余案例展示元信息、安全的 HTTP(S) 原链接和联系作者入口。`需申请权限` 保留访问提示，目标系统独立校验实际使用权限。缺失整个敏感风控字段时视为源权限/结构异常，不发布不完整快照。

已支持「封面」附件：后端缓存图片并返回鉴权媒体路径，空图或加载失败时使用 CSS 档案插图。具体缓存、更新、部署与上传步骤见 [CASE_COVERS.md](CASE_COVERS.md)。没有从原链接自动抓取网页内容，描述缺失时留空。

历史本机分享仅在“我的分享”展示，不插到首页前三条或官方案例库。资讯不属于此接口；Banner 使用独立的飞书表与缓存，见 [BANNER.md](BANNER.md)。

## 点赞与收藏

互动主库是 SQLite。服务器路径默认为 `/var/lib/ows-community/case-interactions.sqlite3`，通过 `OWS_COMMUNITY_CASE_INTERACTIONS_DB` 可指定其他持久路径。蓝绿 API 共用该文件。首次访问从飞书完整导入既有互动，成功后使用本地读写。每次状态变更、计数和待同步记录在同一事务内提交。后台将最新状态同步到案例库同一 Base 的「点赞收藏表」，失败后重试。文本列「案例ID」保存案例原始 record_id。每个飞书账号与案例共用一行，两项操作各有独立的勾选字段和时间字段。取消操作会清掉对应的勾选状态和时间，再次操作使用新的时间。

部署配置为 OWS_COMMUNITY_CASES_ENGAGEMENT_TABLE_ID。现有案例表 tbldtSGzcfa6twD0 默认绑定 tblUTQgRmYHxdiuh。其他案例来源需指定相应互动表，站点的飞书应用需要能读取和写入该表。

OWS_COMMUNITY_CASE_PERSONAL_LISTS 第一位控制「我的点赞」，第二位控制「我的收藏」。00 隐藏两个集合，01 仅展示收藏（默认），10 仅展示点赞，11 同时展示两个。卡片和详情的互动按钮在四种设置下均可使用。

GET /api/v1/cases/engagement 返回可见案例的有效人数和当前账号状态。可传 personal=like 或 personal=favorite 获取已启用的个人集合。PUT /api/v1/cases/{case_id}/engagement/{action} 接收布尔字段 active，并返回确认后的状态。两端点要求飞书登录，沿用案例来源租户限制。案例目录的可见性更新沿用现有同步周期。目录回退到过期快照时暂停个人列表和互动写入。

首次蓝绿切换会等待发布成功标记及旧写请求完成再导入，导入失败可重试。回退到使用飞书作为互动主库的旧版本前，应暂停互动写入、排空投影队列并确认两端数据一致。恢复旧版写入后，再升级时需要重新核对并迁移回退期间的互动。日常备份应覆盖这份独立数据库，在线备份使用 SQLite backup API，以包含 WAL 中已提交的事务。

### 案例虚拟币

每个案例对应的币数为 `2 × floor(min(有效点赞数, 有效收藏数) / 5)`。每升一档给第一作者记 +2，跌破一档给该档原收款人记 −2，重新达标另记一笔。按账号分别统计两类有效互动，两类互动可以来自不同的人。首次迁移按当时仍可见案例的有效互动结算。缺少可唯一识别的第一作者时，保留该案例的待办，补齐后再入账。

独立飞书 Base「OWS 社区虚拟币账本」中的「案例奖励流水」记录作者、案例、两项计数、变动额、档位余额、结算序号和时间。生产应用需要能写入此表。飞书中断或拒绝写入时，本地 SQLite 保留各次跨档事件，恢复后按每个案例的顺序逐笔投递。可通过 OWS_COMMUNITY_COIN_BASE_TOKEN 和 OWS_COMMUNITY_COIN_TABLE_ID 成对指定其他账本。
